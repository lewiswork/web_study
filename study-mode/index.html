Claude Code MCP 활용 계획

전 구간에서 Claude Code를 짝 프로그래머로 쓰되, MCP 서버로 실제 환경(DB·저장소·브라우저)에 직접 연결해 "물어보고 → 바로 확인"하는 루프를 만듭니다.

Postgres MCP
DB · 통합 주차 핵심

로컬/클라우드 Postgres에 직접 연결해 스키마 확인, 쿼리 실행, 마이그레이션 결과를 대화 안에서 바로 검증합니다.

GitHub MCP
전 구간 상시

이슈·PR 생성과 브랜치 관리를 맡겨 주차별 진행 기록을 커밋/PR 단위로 남깁니다.

Playwright MCP
테스트·통합 주차

실제 브라우저를 띄워 화면을 확인하고, 회원가입~핵심 기능 시나리오를 E2E로 직접 실행합니다.

Filesystem (기본 내장)
전 구간 상시

프로젝트 구조 탐색과 리팩터링에 사용. 별도 설치 없이 바로 사용 가능합니다.

0주차에 claude mcp add로 Postgres·GitHub MCP를 먼저 등록하고, .mcp.json을 리포지토리에 커밋해두면 설정을 그대로 공유·재사용할 수 있습니다.

12주 로드맵

0주차
SETUP

환경 구성 & MCP 연결

  • Node.js LTS, pnpm, PostgreSQL(로컬 또는 Docker) 설치
  • create-next-app로 TypeScript + Tailwind + App Router 프로젝트 생성
  • GitHub 리포지토리 생성, 브랜치 전략(main + feature) 확정
  • Claude Code 설치 후 Postgres MCP · GitHub MCP 등록
산출물 — Next.js 프로젝트 스캐폴딩 + MCP 연결 확인
1–2주차
FRONTEND

Next.js UI 기초

  • 컴포넌트/props/state, 이벤트 처리, 리스트 렌더링
  • App Router 파일 기반 라우팅, layout.tsx로 공통 레이아웃 구성
  • Server Component와 Client Component("use client") 구분 기준 익히기
  • TailwindCSS로 레이아웃 스타일링
산출물 — 정적 데이터로 동작하는 UI (예: 게시글 목록/상세)
3주차
FRONTEND

데이터 패칭 & 폼

  • Server Component에서 async/await로 직접 데이터 조회하는 패턴
  • 클라이언트 상호작용이 필요한 부분만 TanStack Query 도입
  • React Hook Form + Zod로 폼 검증, 필요 시 Zustand로 전역 상태 도입
  • loading.tsx / error.tsx로 라우트 단위 로딩·에러 UI 구성
산출물 — 폼 제출·검증이 되는 화면, 로딩/에러 상태 처리
4–5주차
SERVER

Next.js 서버 로직

  • Route Handler(app/api)와 Server Action의 역할 구분
  • REST API 설계(리소스, 상태코드, 에러 응답 포맷 통일)
  • 요청 검증(Zod), 미들웨어(middleware.ts), 환경변수 관리
  • Auth.js로 인증/인가 연결, 비밀번호 해싱(bcrypt)
산출물 — 인증 흐름 + 리소스 CRUD (DB 연결 전, 목업 데이터)
6주차
DATABASE

PostgreSQL 설계

  • 테이블 설계, 정규화, 관계(1:N, N:M), 인덱스
  • Prisma(또는 Drizzle) 스키마 정의 및 마이그레이션
  • Postgres MCP로 Claude Code에서 직접 쿼리하며 스키마 검증
산출물 — ERD + 마이그레이션 적용된 실제 DB
7–8주차
INTEGRATION

풀스택 통합

  • Server Component/Action에서 실제 DB(Prisma) 직접 호출로 교체
  • Auth.js로 로그인 → 세션 → 보호된 라우트(middleware)까지 인증 흐름 전체 연결
  • Next.js 캐싱/재검증(revalidatePath 등) 개념 이해
  • 페이지네이션, 검색 등 실사용 기능 보강
산출물 — 하나의 Next.js 프로젝트로 완결되는 풀스택 앱(로컬 환경)
9주차
TESTING

테스트 자동화

  • Vitest로 유닛 테스트(유틸/훅/컴포넌트)
  • supertest 등으로 API 통합 테스트
  • Playwright MCP로 회원가입~핵심 기능 E2E 시나리오 실행
산출물 — 핵심 플로우 테스트 스위트 + CI 자동 실행 연결
10–11주차
DEPLOY

CI/CD & 호스팅

  • GitHub Actions로 린트/테스트 자동 실행 CI 구성
  • DB: Neon 또는 Supabase에 프로덕션 Postgres 생성
  • 앱 전체(프론트+서버)를 Vercel 하나에 배포 — 별도 백엔드 서버 배포 불필요
  • 환경변수 등록, main 브랜치 push 시 자동 배포(CD) 확인
산출물 — 실제 URL로 접속 가능한 서비스
12주차
WRAP-UP

종합 정리 & 회고

  • 12주 동안 만든 기능을 하나의 미니 프로젝트로 정리
  • README(설치법·아키텍처·배포 URL) 및 회고 문서 작성
  • 다음 스텝 결정(실시간 기능, 모바일 대응, 성능 최적화 등)
산출물 — 완성된 포트폴리오 프로젝트 + 회고 문서

미니 프로젝트 후보

추천

스터디 그룹 게시판

인증, 댓글(1:N 관계), 검색/페이지네이션까지 이 로드맵의 모든 주차를 자연스럽게 관통하는 범위. 지금 진행하는 스터디 자체를 위한 도구로도 쓸 수 있음.

할 일/프로젝트 보드

보드–카드–라벨의 N:M 관계와 드래그앤드롭 UI까지 다루고 싶다면. 프론트엔드 상호작용 비중이 큼.

북마크 아카이브

외부 API 연동(URL 메타데이터 크롤링)과 태그(N:M) 검색을 경험하고 싶다면. 백엔드 통합 난이도가 조금 더 높음.

배포 전 체크리스트

  • .env 값을 프로덕션/개발로 분리하고, 시크릿은 Vercel 프로젝트 설정에 직접 등록
  • 같은 Vercel 배포 안이라 CORS는 대부분 불필요 — 외부에 API를 별도 공개할 때만 설정
  • DB 커넥션 풀 설정 확인 (서버리스 환경이므로 Prisma pooling/Neon pooler 옵션 점검)
  • /api/health 헬스체크 라우트를 만들어 배포 후 확인
  • 최소 1개의 로그/에러 모니터링 연결 (초기엔 플랫폼 자체 로그로도 충분)
  • 커스텀 도메인 연결 시 HTTPS 자동 적용 여부 확인

진행 팁

  • 매 주차 시작 전 Claude Code에게 "이번 주차 목표"를 프롬프트로 주고 계획을 먼저 검토받기
  • 막힐 때는 코드를 먼저 복붙하기보다 에러 메시지를 그대로 붙여넣고 원인부터 질문하기
  • Postgres MCP로 "이 쿼리 결과가 왜 이렇게 나왔는지"를 그 자리에서 바로 확인하는 습관 들이기
  • 짧게라도 매주 회고를 남기면 12주차 종합 프로젝트 정리 때 그대로 재사용 가능

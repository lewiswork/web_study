# Development Mode — 실전 홈페이지 제작

`../practice-mode`에서 구조와 기능을 검증한 뒤, 실제 회사 데이터와 실제 도메인으로 프로덕션 홈페이지를 제작하는 단계입니다. 패턴은 이미 practice-mode에서 확인했으므로, 여기서는 설명보다 **실행 속도**에 집중합니다.

## 시작 조건

`../practice-mode/README.md`의 Definition of Done 체크리스트가 모두 충족된 상태에서 시작합니다.

## Practice → Development 이관 전략

**추천: practice-mode 코드베이스를 복사해 새 프로젝트로 시작 → 더미 데이터를 실제 데이터로 교체**

이유: 이미 동작이 검증된 구조(스키마, Server Action, 파일 업로드, 이메일 발송)를 재사용하는 편이 처음부터 다시 짜는 것보다 빠르고 안전합니다. Claude Code에게 "practice-mode 코드를 development-mode로 옮기면서 더미 데이터/문구만 실제 값으로 교체해줘"라는 식으로 작업을 맡길 수 있습니다.

## 실제 콘텐츠 준비 체크리스트

작업 시작 전 아래 항목을 최대한 미리 확보해두면 진행이 빨라집니다.

- [ ] 회사소개 문구, 연혁, 비전/미션
- [ ] 로고, 대표 이미지
- [ ] 사업분야별 소개 문구
- [ ] 제품 목록 · 사양 · 이미지
- [ ] 카탈로그 · 데이터시트 PDF
- [ ] 실제 담당자 연락처 및 수신 이메일 주소
- [ ] 사업자 정보(상호, 사업자등록번호, 주소 등 — 푸터 표기용)
- [ ] 개인정보처리방침 문구 (문의·샘플요청 폼에서 개인정보를 수집하므로 필수)

## 실전 전환 작업

- [ ] 실제 도메인 구매/연결, HTTPS 적용 확인
- [ ] 이메일 발신 도메인 인증(Resend 등) — 스팸함으로 분류되지 않도록
- [ ] Neon/Vercel 프로덕션 프로젝트를 practice-mode와 **분리해서** 새로 생성
- [ ] 지도 API(카카오/네이버) 실제 키 발급 및 서비스 도메인 등록

## 3주 로드맵

| 주차 | 작업 | 산출물 |
|---|---|---|
| 1주차 | practice-mode 코드 이관, 실제 정적 콘텐츠(회사소개·사업분야) 반영 | 실제 콘텐츠 기준 정적 페이지 |
| 2주차 | 실제 제품/자료 데이터 입력, 폼 실사용 테스트(실제 이메일 수신 확인), 개인정보처리방침 페이지 추가 | 전 기능이 실제 데이터로 동작 |
| 3주차 | 최종 QA(반응형·SEO·성능), 도메인 연결 및 런칭 | 실제 도메인으로 서비스되는 회사 홈페이지 |

## 런칭 후 체크리스트

- [ ] `.env` 프로덕션 값과 시크릿을 Vercel 프로젝트(실전용)에 등록
- [ ] `/api/health` 헬스체크 라우트 배포 후 확인
- [ ] DB 커넥션 풀(Neon pooler) 설정 확인
- [ ] 로그/에러 모니터링 연결
- [ ] 커스텀 도메인 HTTPS 자동 적용 확인
- [ ] 문의·샘플요청 데이터 백업/보관 정책 정하기(개인정보 보관기간 포함)

## 유지보수 계획

콘텐츠(제품 추가, 자료 갱신 등) 변경이 잦아지면 그때 간단한 관리자 화면 도입을 검토합니다. 그 전까지는 Claude Code로 코드를 직접 수정하는 방식으로도 충분합니다.

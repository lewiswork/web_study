기술 스택 결정 — Next.js 풀스택

영역선택세부 옵션비고
애플리케이션 Next.js (App Router) + TypeScript React UI + Node.js 서버 로직이 한 프로젝트/한 배포에 통합 Route Handler·Server Action이 곧 백엔드, 별도 Express 서버 불필요
스타일링 TailwindCSS + shadcn/ui 컴포넌트 디자인 시스템·컴포넌트 재사용 학습에 유리
데이터 패칭 Server Component에서 직접 조회 클라이언트 상호작용에는 TanStack Query, 로컬 상태는 Zustand 초기 로딩은 서버에서, 이후 갱신만 클라이언트에서 처리하는 패턴
서버 로직 Route Handler(app/api) / Server Action 외부에 노출할 API는 Route Handler, 폼 제출 등 내부용은 Server Action REST 설계 원칙(상태코드·에러 포맷)은 Route Handler에도 동일 적용
ORM Prisma 또는 Drizzle ORM Prisma: 생산성·문서화 / Drizzle: 가볍고 SQL에 가까움
Database PostgreSQL Neon 또는 Supabase (서버리스 Postgres) 로컬 개발 후 그대로 클라우드로 이전 쉬움
인증 Auth.js (NextAuth) 세션/미들웨어가 App Router와 바로 통합됨 직접 JWT 구현보다 Next.js와의 궁합이 좋아 기본안으로 격상
테스트 Vitest + Playwright(E2E) Route Handler·Server Action 모두 동일 도구로 테스트
배포 Vercel 하나로 통합 DB만 Neon / Supabase로 분리 프론트·백엔드 별도 배포가 필요 없어 구성이 단순함
왜 Next.js인가. 프론트엔드와 백엔드를 하나의 배포 단위로 묶어 인프라 구성을 단순화하고, SSR·캐싱·로딩/에러 바운더리 같은 실무 패턴을 자연스럽게 익힐 수 있습니다. 대신 Route Handler와 Server Action 중 무엇을 언제 쓸지 판단하는 감각이 별도로 필요합니다 — 이 부분은 4–5주차와 7–8주차에서 집중적으로 다룹니다.

Claude Code MCP 활용 계획

전 구간에서 Claude Code를 짝 프로그래머로 쓰되, MCP 서버로 실제 환경(DB·저장소·브라우저)에 직접 연결해 "물어보고 → 바로 확인"하는 루프를 만듭니다.

Postgres MCP
DB · 통합 주차 핵심

로컬/클라우드 Postgres에 직접 연결해 스키마 확인, 쿼리 실행, 마이그레이션 결과를 대화 안에서 바로 검증합니다. Server Component·Action이 실제로 어떤 데이터를 받는지 확인할 때도 유용합니다.

GitHub MCP
전 구간 상시

이슈·PR 생성과 브랜치 관리를 맡겨 주차별 진행 기록을 커밋/PR 단위로 남깁니다.

Playwright MCP
테스트·통합 주차

실제 브라우저를 띄워 화면을 확인하고, 회원가입~핵심 기능 시나리오를 E2E로 직접 실행합니다.

Filesystem (기본 내장)
전 구간 상시

프로젝트 구조 탐색과 리팩터링에 사용. 별도 설치 없이 바로 사용 가능합니다.

0주차에 claude mcp add로 Postgres·GitHub MCP를 먼저 등록하고, .mcp.json을 리포지토리에 커밋해두면 스터디원 모두 동일한 설정을 공유할 수 있습니다.

할 일/프로젝트 보드

보드–카드–라벨의 N:M 관계와 드래그앤드롭 UI까지 다루고 싶다면. 프론트엔드 상호작용 비중이 큼.

북마크 아카이브

외부 API 연동(URL 메타데이터 크롤링)과 태그(N:M) 검색을 경험하고 싶다면. 백엔드 통합 난이도가 조금 더 높음.

배포 전 체크리스트

  • .env 값을 프로덕션/개발로 분리하고, 시크릿은 Vercel 프로젝트 설정에 직접 등록
  • 같은 Vercel 배포 안이라 CORS는 대부분 불필요 — 외부에 API를 별도 공개할 때만 설정
  • DB 커넥션 풀 설정 확인 (서버리스 환경이므로 Prisma pooling/Neon pooler 옵션 점검)
  • /api/health 헬스체크 라우트를 만들어 배포 후 확인
  • 최소 1개의 로그/에러 모니터링 연결 (초기엔 플랫폼 자체 로그로도 충분)
  • 커스텀 도메인 연결 시 HTTPS 자동 적용 여부 확인

진행 팁

기술 스택 — 가볍게 구성

영역선택비고
프레임워크 Next.js (App Router) + TailwindCSS 스터디에서 쓰던 스택 그대로 재사용
정적 콘텐츠 코드 내 JSON/MDX로 직접 관리 별도 CMS 없이 시작 — 콘텐츠 변경이 잦아지면 그때 도입 검토
제품·문의 데이터 PostgreSQL(Neon) + Prisma 무료 티어로 충분한 규모
파일 저장 Vercel Blob 또는 Cloudflare R2 카탈로그 PDF, 문의 첨부파일용
이메일 알림 Resend 또는 Nodemailer + SMTP 샘플요청·문의 접수 시 담당자에게 즉시 알림
스팸 방지 Honeypot 필드 + Cloudflare Turnstile reCAPTCHA보다 가볍고 사용자 마찰이 적음
SEO next/image, sitemap.xml, robots.txt 회사 홈페이지는 검색 노출이 핵심 지표
배포 Vercel + 커스텀 도메인 스터디 때와 동일한 배포 방식
과설계 주의. "특별한 기능이 없는" 사이트인 만큼 관리자 페이지·CMS는 처음부터 만들지 않는 것을 추천합니다. 정적 콘텐츠는 코드로 직접 수정하고, 문의·샘플요청은 이메일 알림만으로 시작한 뒤 접수량이 늘어나면 그때 간단한 목록 조회 화면을 추가하세요.

반응형(모바일) 체크리스트

  • 모바일 퍼스트 기준 브레이크포인트 정의 (360 / 768 / 1024 / 1280)
  • 헤더 내비게이션은 모바일에서 햄버거 메뉴로 전환, 터치 타겟 44px 이상 확보
  • next/image로 반응형 이미지(자동 srcset) 적용
  • 폼 입력 필드에 맞는 모바일 키보드 타입 지정 (전화번호 tel, 이메일 email)
  • 전화·이메일·다운로드 링크가 모바일에서 자연스럽게 동작하는지 확인 (tel:, mailto:)
  • iOS Safari, Android Chrome 실기기(또는 원격 디버깅)로 최소 1회 점검

# Practice Mode — 연습용 홈페이지 제작

`../study-mode`에서 배운 스킬을 실제로 만들 회사 홈페이지와 **동일한 구조**에, 더미(가짜) 데이터로 먼저 적용해보는 리허설 단계입니다. 매 단계마다 Claude Code에게 "왜 이렇게 하는지" 설명을 받으며 천천히 진행하고, 여기서 검증된 코드는 `../development-mode`로 그대로 옮겨갑니다.

## 목적

- 실제 회사 정보/도메인이 아직 준비되지 않아도 지금 바로 시작 가능
- 더미 데이터로 진행하므로 실수해도 부담 없음 — 배우는 데 집중
- Development Mode 진입 전, 구조·기능·배포 흐름을 한 번 통째로 검증

## 진행 방식 — 설명받으며 진행하기

1. 작업 전에 "이번에 만들 것 + 왜 필요한지"를 Claude Code에게 목표로 제시
2. 코드가 생성되면 바로 다음으로 넘어가지 말고 "이 코드가 어떤 흐름으로 동작하는지" 설명 요청
3. Postgres MCP로 실제 쿼리/스키마를 직접 열어보며 개념을 눈으로 확인
4. 막히면 에러 메시지를 그대로 붙여넣고 원인부터 질문(정답 코드보다 원인 이해 우선)
5. 각 주차 끝에 "이 부분을 내가 직접 설명할 수 있는가"를 스스로 체크

## 더미 콘텐츠 전략

실제 콘텐츠 대신 아래와 같은 플레이스홀더 데이터셋을 먼저 준비합니다.

- 가상 회사명 1개 (예: "○○테크")
- 가상 제품 3–5개 (이름, 카테고리, 짧은 설명, 이미지 placeholder)
- 샘플 자료 PDF 2–3개 (아무 문서나 더미로 사용 가능)
- 가상 사업분야 2–3개

## 사이트 구조 (실제 홈페이지와 동일하게 연습)

| 페이지 | 핵심 콘텐츠 | 데이터 소스 | 비고 |
|---|---|---|---|
| 홈 | 히어로, 사업분야 요약, 대표 제품, CTA | 더미 정적(JSON/MDX) | 반응형 히어로 |
| 회사 소개 | 연혁, 비전, 오시는 길(지도) | 더미 정적 | 지도는 카카오/네이버 지도 API |
| 사업 분야 | 분야별 소개 카드 | 더미 정적 | 모바일 1열 스택 |
| 제품 소개 | 목록(카테고리 필터) + 상세 | DB(Product 테이블) | 더미 제품 3–5개로 CRUD 연습 |
| 자료실 | PDF 다운로드 | DB(파일 메타) + 파일 스토리지 | 더미 PDF로 업로드/다운로드 흐름 연습 |
| 샘플 요청 | 폼(회사명·담당자·연락처 등) | DB 저장 + 이메일 알림 | 본인 이메일로 테스트 수신 |
| 기술지원 문의 | 폼(문의 유형·내용·첨부) | DB 저장 + 이메일 알림 | 스팸 방지 로직도 연습 |

## 기술 스택 (실습용, 전부 무료 티어)

| 영역 | 선택 |
|---|---|
| 프레임워크 | Next.js(App Router) + TailwindCSS |
| 제품/문의 데이터 | PostgreSQL(Neon 무료 티어) + Prisma |
| 파일 저장 | Vercel Blob 또는 Cloudflare R2 |
| 이메일 알림 | Resend(개발자 본인 이메일로 테스트 발송) |
| 스팸 방지 | Honeypot 필드 (Turnstile은 선택) |
| 배포 | Vercel (스테이징 프로젝트로 별도 생성) |

## 6주 로드맵

| 주차 | 태그 | 작업 | 이번 주 배우는 개념 | 산출물 |
|---|---|---|---|---|
| 1주차 | 기획 | IA/와이어프레임, 더미 콘텐츠 준비 | 정보구조 설계, 콘텐츠 우선 접근 | 페이지별 콘텐츠 초안 + 와이어프레임 |
| 2주차 | 퍼블리싱 | 헤더(햄버거 메뉴)·푸터 공통 레이아웃 | 반응형 브레이크포인트, 레이아웃 컴포넌트 설계 | 재사용 가능한 공통 레이아웃 |
| 3주차 | 퍼블리싱 | 홈/회사소개/사업분야/제품소개(정적) | Server Component 정적 렌더링 | 더미 콘텐츠 기준 완성된 페이지 7종 |
| 4주차 | 기능 구현 | 제품 DB 이전, 자료실 다운로드, 샘플요청/문의 폼(Server Action) | Prisma 스키마 설계, 파일 업로드, 폼 → DB → 이메일 흐름 | 더미 데이터로 전 기능 동작 |
| 5주차 | QA | 실기기 반응형 점검, SEO 기본 설정, 폼 유효성 검증 | 반응형 디버깅, 메타태그/sitemap | 체크리스트 통과 상태 |
| 6주차 | 배포 | Vercel 스테이징 배포, 이메일 수신 테스트 | CI/CD, 환경변수 관리 | 스테이징 URL로 접속 가능한 연습용 사이트 |

## Practice Mode 완료 기준 (Definition of Done)

- [ ] 더미 데이터로 7개 페이지 모두 모바일/데스크톱에서 정상 동작
- [ ] 샘플요청·기술지원 문의 폼 제출 → DB 저장 → 이메일 알림까지 전체 플로우 확인
- [ ] 자료실 다운로드 기능 정상 동작
- [ ] Vercel 스테이징 배포 성공
- [ ] Prisma 스키마, Server Action, 파일 업로드, 이메일 발송 로직을 스스로 설명할 수 있음

## Development Mode로 넘어가는 조건

위 체크리스트를 모두 충족하면 `../development-mode/README.md`로 이동해 실전 제작을 시작합니다.
